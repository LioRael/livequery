# macOS deadline diagnosis: build/measurement separation

The workflow builds an unmodified official source archive at 12fa024 and a second archive with the explicit diagnostic patch on a build VM. It uploads both binaries, SHA256 values, source/patch identity and toolchain metadata. Four fresh macOS 26 measurement jobs download the same artifact: official/diagnostic × sync/async. Measurement jobs install no toolchain and perform no compilation. They verify hashes, restore executable permission, and record their own OS/image/CPU provenance separately from build provenance.

Each job runs once for 300 seconds: 5000 rows, 96-byte strings, four observers, original publish/poll periods, business traffic and 100ms wall deadline. The original check-load.py controls the result. The newly invented 25% CPU admission gate has been removed at the user's direction. No retry, timeout relaxation or traffic reduction is added. Known conflicting build/profiler/workload processes and cooperative overlap are still rejected.

Only the disposable hosted VM's previously observed indexing activity is isolated (mdutil plus the two verified user indexing agents); other OS/security services are untouched. A fixed 180-second settling interval occurs after artifact download. This does not guarantee physical-host CPU exclusivity.

Every measurement records actual HOST_CPU_LOAD_INFO tick deltas and process-name/decaying-CPU snapshots every five seconds during workload, with the same CLOCK_MONOTONIC basis. CPU activity is evidence, never a workload failure by itself. The diagnostic variant additionally records stage wall/CPU/allocator timing and 10ms thread/process-counter samples. Correlation attaches overlapping five-second host CPU windows to slow phase intervals; these broad windows cannot establish exact causation inside a millisecond-scale gap. The official binary has the prior bounded capture wall/CPU diagnostics but no exact absolute capture timestamps; do not pretend it has the instrumented variant's temporal resolution.

The variants run on different VMs, so their difference is not a controlled same-host estimate of probe overhead. The official variant avoids confusing instrumentation-induced latency with release behavior. Neither five-minute run replaces the original full OS/engine baseline/task endurance or final release checks. No macOS 15 substitution is made.
